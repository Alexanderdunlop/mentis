# @mentis/engine — a model-first inline contentEditable engine, built to replace mentis v1's internals; mentions are its demo, not its purpose

- **This is a learning project, optimised for interesting over shipping.** When a decision is ambiguous, pick the option that teaches more. Never introduce migration deadlines, backwards-compatibility pressure, or release urgency here. The package is `private: true` — keep it that way. Full context in `docs/plan.md`.
- **`packages/mentis` is frozen at 0.2.x**: bug fixes and test coverage only. Don't add capability there to close a gap this package is meant to close.
- **One idea per file.** A file that needs "and" to describe it is two files. Split rather than grow — this package optimises for reviewability over locality, and the largest file is deliberately under ~150 lines.
- **Prefer plain exported functions over classes**, and keep mutable state in a single wiring module at the edge (`create-*.ts`) rather than spread through the logic it coordinates. `log/describe-event.ts` against `log/create-event-log.ts` is the pattern: pure description separated from listener plumbing, which is what makes the description testable.
- **The DOM is a projection of the model, never a source.** `beforeinput` is always `preventDefault`ed and the DOM changes only through `render`, which patches text nodes in place — never `innerHTML`. Anything that writes to the editor element behind the model's back desyncs the one invariant this package exists to hold.
- **Undo is the single exception to "beforeinput only"** (ADR 0007). The engine watches ⌘Z/Ctrl+Z/Ctrl+Y because preventing every `beforeinput` leaves the browser's undo stack empty, so ⌘Z fires nothing — `historyUndo` alone would mean undo silently never working. Both routes are handled. Don't add other keys to that listener without an ADR; the mention dropdown's keys live in the consumer for exactly this reason.
- **Undo granularity follows word boundaries, never typing speed** (ADR 0008). Whitespace closes a group; timing is only a 3s idle guard. A speed-dependent rule is both unpredictable for the user and untestable — a Playwright assertion about undo would be flaky by construction.
- **History records inverses, never document snapshots**, and the stack is pure — timestamps are passed in, never read from a clock inside it. A transaction with `origin: "history"` must never be recorded, or undo becomes a loop.
- **Caret movement is the browser's job, editing is ours** (ADR 0003). Don't add `keydown` handlers for arrows, Home/End, or `Selection.modify` — the selection is read back on demand instead. The cost lands in M2: a caret can sit somewhere the model forbids, so atoms must *correct* the selection rather than prevent it.
- **Take edit ranges from `InputEvent.getTargetRanges()`, not from the selection** (ADR 0004). The browser has already resolved grapheme clusters, word-delete boundaries and what autocorrect is replacing. A collapsed range *from the browser* means delete nothing — widening it turns a word delete into a character delete. Our own selection read is a marked fallback and is knowingly wrong for graphemes.
- **`white-space: pre-wrap` is behaviour, not styling** (ADR 0002). Without it a `\n` in a text node doesn't render as a break and the model is right while the screen is wrong, with no error. `createEditor` sets it on the element; don't move it to a stylesheet.
- **A trailing `<br>` is a rendering artifact with no model counterpart.** It exists only so the caret can sit on a final empty line. Never count it in position mapping — that's what `view/dom-text-nodes.ts` filters.
- **An unknown `inputType` returns null and gets reported, never guessed at.** Silently mishandling one is how editors corrupt documents on platforms the author never tested.
- **Nothing below `adapters/` may import a framework.** This is the whole reason the eventual React/Vue/vanilla wrappers can be ~100 lines each. It applies to the devtools too.
- **The `logic` vitest project has no DOM at all** (`environment: node`). If something there starts needing one, that's a design signal, not a reason to change the environment. `*.dom.test.ts` runs under happy-dom for "does it throw" and coarse structure — **never** caret semantics, which are approximations there. Real caret behaviour is asserted in `e2e/` only; see `e2e/CLAUDE.md`, which owns that boundary and the "add an e2e test to prevent this in future" recipe.
- **CI does not run this package, on purpose.** `unit-test.yml` is scoped `--filter mentis` so a `private: true` experiment can never block a mentis bug fix or release. Don't "fix" that by adding engine steps — run `pnpm --filter @mentis/engine typecheck` and `... test` locally instead, and treat them as required before any commit here.
- **The mention query is derived, never stored** (ADR 0006). `mentionQuery({doc, selection})` is pure — recompute it, don't cache it, and don't add detect/clear events. That pattern is what left the archived v2 branch with menus open over stale text.
- **The dropdown and its keyboard belong to the consumer, not the engine.** Arrow/Enter/Escape/Tab while a menu is open are handled in `dev/` (and will be in the M7 adapters), because ADR 0003 confines the engine to `beforeinput`. Preventing the Enter keydown is also what stops it reaching `beforeinput` as a newline.
- **There are two coordinate spaces and mixing them is the main footgun here.** *Position space* (`docLength`, `nodeLength`, `sliceLength`) is what selections, ranges and steps use. *Visible text* (`docText`, `sliceText`, `nodeText`) is what the reader sees and what DOM `textContent` equals. They coincide only for documents with no mentions, so `docText(doc).length` is never a valid position — code that assumes otherwise fails only once a mention exists. See ADR 0005.
- **An atom is one position wide**, so a position inside a mention is unrepresentable. Don't add a pass that pushes the selection out of an atom; `domToModel` snaps an interior DOM boundary to the nearer edge and that is the whole mechanism.
- **Steps carry a slice, not a string.** A string-based inverse restores a deleted mention as its label text — silently, and only on undo. Use `replaceWithText` for the plain-text case rather than reaching back for a string step.
- **Never compare a character against `" "`.** A non-breaking space (U+00A0) renders identically but fails `===`, while `/\s/` matches it — so regex checks pass by accident and equality checks fail silently. Normalise once at the model boundary, not per call site.
- **Never measure caret offsets with `Range.toString()`.** It returns only `Text` data and ignores `<br>`, so every offset after a line break is off by one. Use `dom/text-length.ts`.
- **Browsers disagree about whether a line break costs a character.** Firefox inserts a literal `"\n"` that counts in `textContent`; Chromium and WebKit end the line with a block boundary that does not. `docs/adr/0001-line-breaks-as-newline-characters.md` commits this package to one `\n` per break and therefore owes a normalisation step at the DOM boundary — treat any offset arithmetic spanning a newline as unproven until M1 settles it.
- **Never type invisible characters literally into source.** Name them by code point (`String.fromCodePoint(0x00a0)`). Two look-alike invisible characters silently become a duplicate object key, and no reviewer can see the difference.
- **Script-created events cannot cause editing** — they are `isTrusted: false`, so the browser skips the default action. Use `document.execCommand` when you need a genuine `beforeinput`/`input` pair on the native undo stack, and accept that IME and mobile autocorrect can only be exercised by hand or through Playwright/CDP.
- **In `packages/mentis` the DOM *is* the state** — `extractMentionData` re-derives truth from it every keystroke, so any DOM quirk is a correctness bug. That is the reason this package exists; don't replicate the pattern here.
- **Don't rebase or revive `overhaul-html-node-logic`.** It's an archived design sketch, 11 months stale, with a conflicting `extractMentionData` rewrite on main. Only its `v2/mention-query/*` logic and tests are worth salvaging.
- **Record decisions, not facts.** A commitment future work inherits goes in `docs/adr/` with an explicit revisit-when trigger; a platform trap that will bite again goes in `docs/notes/contenteditable-traps.md`; a local "don't break this" goes in a comment at the line. The test is whether someone returning after a month away would find it — code comments fail it, because you have to already be in the file.
- **Work happens in parallel git worktrees.** Each needs its own `pnpm install`; they don't share `node_modules`.
- **Done means typecheck and tests green before the commit, and green CI on the PR.** State plainly what is still unverified — browser-only behaviour especially, since no local check covers it.
