# @mentis/engine e2e — the engine's own browser matrix

- **This layer is an observer, not a fixer.** A spec that reveals engine behaviour worth changing gets `test.fixme()` and a comment naming the cause — never a change to `packages/engine/src/` from here. The reason is on the wall in `e2e/CLAUDE.md` for v1: commit `a6fcfd0` bent production code to satisfy a fake DOM. Bending it to satisfy one browser is the same mistake with a better disguise.
- **It runs on its own Playwright config, deliberately, and must stay that way.** `packages/engine/CLAUDE.md` says CI does not run this package on purpose, so a `private: true` experiment can never block a mentis bug fix or release. Adding engine projects to the root `playwright.config.ts` would hand this experiment exactly that power over `pnpm test:e2e`. Reuse the *shape* — same four projects, same reporters, same conventions — never the same run.
- **The engine workflow is nightly and manual only.** `engine-e2e.yml` has no `pull_request` trigger for the same reason. If you want it on PRs, that is a change to the isolation rule and needs to be argued, not assumed.
- **Specs mirror ADRs, one file per ADR that makes a browser-observable claim.** `spec/adr-0005-atoms.spec.ts`, `spec/adr-0013-graphemes.spec.ts`, and so on. Every ADR in `docs/adr/` has an **Unverified** section; this directory is where those get discharged, and the mirroring is what stops a claim quietly outliving its evidence. When an ADR's unverified list shrinks, its spec file is why — say so in the ADR.
- **Assert the model *and* the DOM.** `expectModelMatchesDom()` is the invariant this whole package exists to hold — the DOM is a projection of the model — and it is not checkable anywhere but a real browser. Call it liberally; it is cheap and it is the point.
- **Position space is not character space** (ADR 0005). `model().selection` and `domCaretOffset()` deliberately disagree for any document containing a mention. Asserting both is how a spec proves that divergence is real rather than theoretical; asserting only one hides the bug class the whole design exists to prevent.
- **Never assert against `dev/index.html`.** That is the inspector — a scratchpad that grows a new panel whenever a milestone needs one. Specs drive `dev/e2e.html` only, on port **5280** rather than the inspector's 5180, so a suite run can never attach to an inspector left open during development.
- **Drive the editor as a user, read the model to check.** The harness deliberately does **not** expose the `Editor` object or `dispatch`. A spec that could set up state the input pipeline cannot produce is a spec that proves something about itself.
- **Browsers disagree about how much one delete covers, and it is still not a bug to fix from here.** [ADR 0014](../docs/adr/0014-clamp-a-forward-delete-to-an-atom.md) settled the question this bullet used to leave open, and split it: **grapheme extent stays the browser's** (Firefox peels a cluster backwards, takes it whole forwards — a convention, pinned per engine in `spec/adr-0014-delete-granularity.spec.ts`, never asserted as one answer across the matrix), while **a forward delete at an atom is clamped to the atom** in `src/input/transaction-for.ts`. Note how that fix arrived: a decision and an ADR first, then unit tests, then this layer recording the outcome — not a change to `src/` made to turn a spec green. That order is the rule, and ADR 0014 is the argument that must be made again before a second exception is added.
- **"Nothing is corrupted" is not "nothing is broken", and one document is not a phenomenon.** The trailing-chip case — Firefox reporting a *collapsed* range, so Delete could not remove a chip at all — sat under a `test.fixme` labelled "granularity" for a day, because the first probe happened to have a space after the chip. When an engine diverges, probe the whole family (before/after text, letter, emoji, another atom, end of document) before deciding what kind of thing you are looking at.
- **If a spec needs `page.evaluate`, a fixture helper is missing.** Add it to `fixtures/harness.ts` so the next spec gets it free.
- **Caret offsets are not portable across a newline** — Firefox counts a literal `\n` in `textContent`, Chromium and WebKit do not. The engine is supposed to make that invisible by owning the break itself (ADR 0001/0002), so assert the *model* length rather than a DOM offset once content contains a newline.
- **Run it:** `pnpm --filter @mentis/engine test:e2e:chromium` for the fast loop, `... test:e2e` for all four projects, `... typecheck:e2e` for types. Browsers come from `pnpm exec playwright install`.
